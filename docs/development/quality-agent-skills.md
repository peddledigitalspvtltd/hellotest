# Quality agent default skills

The five agents in Agent Studio have distinct default methods in the versioned [skill catalog](../../services/agentic/shared/qualityAgentSkills.json), assembled by [qualityAgentSkills](../../services/agentic/backend/services/qualityAgentSkills.js). The default methods and output rules are system instructions. The request, page text, retrieved documents and tool results remain untrusted data. User-added node instructions can refine the requested task; they do not grant extra browser actions, network origins, time, model budget or tool permissions.

The catalog is reviewed on **2026-10-31**, version **1.0.0**. It contains short original method summaries and primary reference links. Repository URLs are methodology references, not fetched source code, installed packages, new model tools, or proof that an audit ran. Full repository manuals are not copied into every request. The task brief carries only the skill ID and version; the default system block carries the selected agent's methods and references once.

The references support concrete distinctions. Playwright recommends user-facing locator contracts and consistent screenshot environments. ZAP's baseline method spiders and performs passive checks; mentioning it does not authorize active probes. The axe-core project documents incomplete checks needing manual review. Web Vitals measurement depends on the page lifecycle and interactions. The pixelmatch API distinguishes a per-pixel perceptual threshold from a permitted share of differing pixels. These distinctions are preserved in the default prompts so a public library name cannot become an unsupported claim of execution.

## Actual visual model evidence

[qualityAgentVisualEvidence](../../services/agentic/backend/services/qualityAgentVisualEvidence.js) prepares the current screenshot, its explicitly reviewed baseline, and an optional diff image as actual inline image inputs. It accepts only injected service readers that already authorize the signed-in actor against the quality run and baseline. It independently verifies project/application/target scope, artifact identity, content type, exact byte count and SHA-256. The baseline must match the selected baseline ID, target, viewport and masks and retain its reviewer and source run. Arbitrary artifact URLs and image URLs from request data are never fetched.

The helper uses the shared `aiReferenceImages` raster validation and bounded data-URL contract: at most three unique PNG images and 950,000 encoded characters in total, with original artifacts capped at 8 MB. Identical current/baseline bytes are sent once while both evidence identities remain in the manifest. Fixed user-message labels identify each image and explicitly treat visible text as untrusted evidence. The original private quality artifacts remain the retained source; `persistReferenceImages: false` keeps the shared `aiAttachmentAccess` preparation path from uploading duplicate evidence or introducing unrelated attachment permissions and public links.

An explicit `supports_vision: false` model setting produces a disclosed manifest-only assessment without reading image bytes. Unknown private model names are not guessed to be text-only. If the required current/baseline pair exceeds the image budget, no partial pair is sent; the manifest records the limitation. An optional diff can be omitted with its omission recorded when the current and baseline already fill the budget. Revoked authorization, changed checksums and invalid rasters stop dispatch rather than becoming a silent image fallback. Provider vision rejection remains an actionable model error, never permission to retry after removing the images.

The visual manifest records whether image input was prepared, which identities map to each image index, whether both comparison images are present, and any omissions. Preparing bytes does not by itself prove provider receipt. The final validated model call and its trace establish the actual request outcome. The model can describe visible regions only for supplied images; a manifest-only result is explicitly limited to measured metrics and retained metadata.

## Prompt phases and output contract

`instructionBlock(kind, { phase })` supports `planning`, `decision` and `assessment`:

- Planning proposes only supported, reviewable steps using authorized locator context and never claims to have observed a page.
- Decisions select the next supported action from the current observation and wait for its tool result. Progress is a concise observable summary; hidden model reasoning is not a UI output contract.
- Assessment explains recorded findings and metrics and proposes next steps. Finding IDs, artifact IDs, metric keys and reference IDs must come from the supplied evidence manifest. The model cannot replace the engine outcome or create a new measurement by writing text.

The assessment validator and worker own the final machine schema and identity checks. The skill catalog supplies methods, evidence boundaries and output guidance, without duplicating the validator's complete schema. Any missing or truncated evidence must remain an explicit limitation rather than an invented successful result.

`node --test services/agentic/test/backend/qualityAgentSkills.test.js` checks all five intents, allowed primary references, phase-specific boundaries, prompt size, stable task ownership, immutable defaults and rejection of unknown policy phases. Runtime and stream tests verify that these methods reach the actual dispatched requests and do not turn provisional text into a completed outcome.

`node --test services/agentic/test/backend/qualityAgentVisualEvidence.test.js` verifies exact current/baseline/diff bytes in image parts, authorization and integrity failures, baseline policy pinning, no external URL access, image budgets without misleading partial pairs, optional omissions, identical-image deduplication, unsupported-model disclosure and cancellation. These fixtures use real bounded PNG data and no paid model calls.
