# n8n core-node coverage inventory

Reviewed **2026-10-31** against the official [complete documentation index](https://docs.n8n.io/llms.txt), [core-node index](https://docs.n8n.io/integrations/builtin/core-nodes/), and all **69 distinct root core-node documentation URLs** listed in that snapshot. Nested troubleshooting, operation-reference, and example pages are not additional nodes. Both Form URLs and the deprecated Activation/Workflow Trigger pages remain explicit rows so nothing disappears through name deduplication. This is a documentation-entry inventory, not a claim that n8n has 69 independent, current runtime features.

The [n8n API node](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.n8n/) manages an n8n instance through its API. It is one row in the inventory, **not** the reference for all n8n node implementations. n8n application connectors, service-specific triggers, cluster subnodes, and community packages lie outside this core-node denominator; none are implicitly installed or supported in HelloTest.

Coverage here means executable workspace code. A palette label, an imported `n8n_payload`, a simulated graph preview, a model's ability to describe an operation, or a generic MCP connection does not establish an adapter. This review does not assert that every managed connection, provider, worker, or external service is configured in a deployment.

## Status definitions and totals

| Status | Entries | Meaning |
| --- | ---: | --- |
| Native subset | 17 | A real HelloTest workflow adapter implements the stated task within the row's bounds. It does not promise every n8n option or payload compatibility. |
| Composition subset | 4 | Existing adapters can perform the stated narrower task; there is no full dedicated equivalent. |
| Platform subset | 5 | A related HelloTest capability exists outside a dedicated graph node, sometimes accessible through the built-in HelloTest MCP connection. The missing graph contract remains explicit. |
| External conditional | 2 | The existing managed HTTP adapter can speak the required JSON API protocol after the actual endpoint and credentials are configured. No external service is bundled by this statement. |
| Unavailable | 41 | No native equivalent or sufficient existing composition is implemented. The row names the missing adapter or infrastructure. |
| **Total** | **69** | **Each upstream root URL appears once in the tables below.** |

Native, composition, and platform subsets must not be added together and presented as full n8n parity. HelloTest's [data-operation contracts](workflow-data-operations.md), [managed credential contract](workflow-credentials.md), and [MCP tool reference](../product/mcp-tool-reference.md) define their exact supported behavior. MCP mutations require the original user to authorize the exact prepared plan; workflow tools cannot approve their own plans.

## Capabilities that must remain explicitly separate

**SQL is not an additional root core-node entry in this snapshot.** It is an option of n8n Merge and also appears in database-specific application connectors. HelloTest Merge has no SQL evaluator. The built-in MCP database tool reads fixed permissioned projections; it cannot execute arbitrary SQL. Implementing SQL would require a dedicated execution/data-source contract, parameter binding, statement permissions, query budgets, and result schemas. Adding a palette label would not satisfy that requirement.

**External HTTP/MCP is a transport, not a catalog of installed adapters.** The existing `apiTool` and `mcpTool` provide real outbound connections, request/schema validation, project scoping, and honest transport receipts. They do not establish that a mail, LDAP, SSH, file, code, or conversion service exists. Such a capability becomes usable only after a real service exposes the needed operation, a project connection is configured, the tool/schema or HTTP contract is inspected, and its outcome and credential rules are supported. The two External conditional rows identify protocols the present adapter can already invoke directly; they remain deployment-dependent.

**Application APIs are not workflow event ingress.** Native HelloTest MCP includes workflow definitions, agent definitions, run submission/status, Knowledge and Test Data Set operations where advertised. It does not turn every workflow into a public MCP tool, add a parent-child subworkflow transaction, or enable schedule/webhook/chat/form triggers. Existing reviewed action-plan requirements remain in force.
