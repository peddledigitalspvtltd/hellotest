# Knowledge model requests

Knowledge requests retain the verified actor/project, source and fragment ACL checks, bounded evidence packet, local output contract, current-access recheck, and citation validation. Compacting a prompt does not broaden retrieval or establish grounding.

The normal assistant answer intentionally uses one intent-planning model call before retrieval and one synthesis call after retrieval. Evidence search performs neither call. An explicit empty retrieval scope or a zero retrieval/evidence budget also skips the intent call; an empty evidence result never starts synthesis. Successful same-turn replay performs no new retrieval or model calls. The separate `requestGroundedVerification` helper remains available to explicit consumers; it is not an automatic third stage in the assistant answer pipeline.

| Stage | Why a separate call exists |
| --- | --- |
| Assistant intent planning | Optional focused retrieval hints before evidence selection; never an answer or authority grant. |
| Assistant synthesis | A cited answer from the final authorized packet, after retrieval has completed. |
| Explicit answer verification | An explicitly invoked audit/rewrite of a draft against the same evidence; not added to ordinary assistant turns. |
| Internal context intent planning | Optional native retrieval path; public MCP context reads and existing planned/prefetched paths use deterministic or supplied plans. |
| Ingestion enrichment | Optional exact source-excerpt hints after canonical text/index readiness; generated prose never replaces source text. |
| Graph relationship extraction | A separately requested, reviewed proposal over already authorized nodes and exact witness passages. It is not an automatic second ingestion pass. |
| Query/document embeddings | Vector retrieval/indexing rather than answer generation; existing batched embedding and bounded local fallback remain separate. |

Initial intent planning sends the question, exact normalized scope, bounded user history for reference resolution, and optional reviewed focus. It omits the empty ContextPacket and audit metadata when no evidence exists yet. If a planner is called with existing evidence, it still receives a valid budgeted ContextPacket. In the deterministic synthetic boundary fixture, the initial user payload falls from 835 to 291 UTF-8 bytes (65%). This measures that fixture's user payload, not tokenizer-specific input tokens or an entire production request.

Synthesis retains one compact ContextPacket and its required citation/output instructions. The explicit verification helper uses the same compact packet projection and compact JSON rather than resending retrieval plans, budget histories, repeated locator fields, and pretty-print whitespace. Canonical packets remain intact for audit. The Knowledge adapter now forwards its declared output schema and validates the buffered result locally with the shared schema validator. A mismatch remains a non-transient invalid-output error, eligible for the existing single bounded synthesis repair. Strict provider schemas are used only when the shared transport verifies the official provider, model and unchanged supported schema; other providers retain schema instructions and local validation.

Malformed synthesis can trigger one bounded regeneration with the same authorized evidence and static correction instructions. A transient transport failure can retry within the existing shared deadline and attempt ceiling. These serve different purposes and remain distinguishable. Invalid or generated text is never promoted into trusted instructions.

The OpenAI-compatible Knowledge adapter negotiates only explicit pre-generation parameter rejections. Every additional compatibility POST now reserves a call and conservative cost budget before dispatch; diagnostics expose `calls_used`, transient `retries_used`, and `compatibility_retries`. `calls_used` counts conservative admission reservations; `provider_requests` counts generation POSTs admitted by the final transport callback. A reservation denied after final prompt preparation therefore consumes admission budget but records zero provider requests. The final transport callback checks the effective payload after managed prompts, schemas and attachments are added, and reserves any extra cost before dispatch. Estimating raw message-marker bytes alone could otherwise admit an expanded request above the caller's ceiling. Failed or missing-usage attempts do not reopen the spending ceiling. A bounded 100-entry, ten-minute cache stores only rejected parameter capabilities, keyed by integration, endpoint and model. It stores no answers, prompts, evidence or credentials. This prevents later stages and transient retries from repeatedly resending a known-rejected request while retaining local JSON validation and the output-token limit.

Native embedding requests enter `knowledgeRag.requestProviderEmbeddings` and use the shared `fetchLlmWithRetry` transport as operation `knowledge.embedding`, recorded under the `ai.knowledge.embedding` configuration view. Integration selection uses the Knowledge Assistant usage mapping and the integration's explicit `embedding_model`; a chat-only model is never probed as an embedding model. The request body contains only `model` and `input`, so chat prompts, sampling settings and answer schemas are not applied. Shared provider traces capture request bytes, dispatch, latency and returned usage. Embeddings are separate from the Knowledge generation gateway's `calls_used`, `provider_requests` and chat cost reservations. An explicit retrieval cost ceiling selects keyword retrieval, preventing an unbudgeted embedding call.

Query plans deduplicate up to ten retrieval queries and share one lazy embedding batch. Provider batches contain at most 64 texts; responses must have exact indices, finite values, consistent dimensions and bounded size. Query vectors are cached for fifteen minutes using a versioned fingerprint of integration ID, endpoint, model and exact input. Changing an integration's endpoint cannot reuse vectors from its former provider. Document ingestion reuses matching input hashes only within the source and embedding configuration and deduplicates missing inputs. Existing deadlines, cancellation, bounded retries and local fallback remain in force. Qdrant reads and writes are vector storage operations, not additional model requests; their candidates remain constrained by fresh source, document and chunk access and version checks.

Behavioral coverage lives in `knowledgeModelEfficiency.test.js`, `knowledgeModelBoundary.test.js`, `knowledgeAssistantExecution.test.js`, `knowledgeModelGateway.test.js`, `knowledgeModelRetry.test.js`, `knowledgeAssistantResilience.test.js`, `knowledgeRetrievalLatency.test.js`, and `knowledgeRagContract.test.js`. Tests cover actual dispatch counts, repeated-request bytes, output bounds, capability and embedding-cache isolation, one shared embedding batch, disabled-retrieval zero calls, same-turn replay, repair limits, cancellation, and access revocation during generation. They use deterministic provider fixtures, not a claim of measured answer quality across live models.
