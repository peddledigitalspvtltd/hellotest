# Application LLM request audit

This audit follows application feature requests under `services/ai`, `manual`, `automation`, `dashboard` and `testing`. It complements the shared transport, Knowledge/Ask HelloTest and agent/workflow audits. It does not treat every browser action, background job or model correction as a duplicate request.

The source scan identifies 16 application files containing 18 `fetchLlmWithRetry(...)` call expressions. Seventeen expressions construct a provider request; the additional expression forwards the separately configured authoring-intent request from Test Case design. Durable Test Case generation and several review features delegate to these callers rather than creating another provider transport.

## Corrections implemented

Structured review previously retried an invalid response with the same original request and a generic correction sentence. It now supplies the invalid candidate and local validation issues, bounded separately from task evidence. Oversized invalid candidates are described by omission metadata and a hash; they are not sliced into misleading partial JSON. Instructions resolve through the requested feature profile. Both normal and smaller evidence projections are sanitized. The accepted input hash identifies the evidence projection actually used, and returned usage explicitly describes the accepted response rather than claiming cumulative provider usage.

Local review corrections now recognize shared transport response-validation errors. They do not retry authentication failures, provider refusals, truncated output, schema configuration errors, unknown transport outcomes or the shared native artifact correction error. This keeps the two correction owners separate.

Assurance previously cut serialized source JSON at 32,000 characters during repair while continuing to advertise references for the omitted sources. It now keeps complete supplied source objects and uses the existing request budget to reject an oversized correction. The computed core review schema is passed through the shared transport instead of duplicating the full machine schema in user data. Missing or malformed automation suitability still normalizes to `unknown` without discarding an otherwise supported review.

Defect triage now removes a source excerpt only when the bounded field already contains that exact excerpt. The original citation identity and field pointer remain available. A source-only value, including delivery-scope evidence absent from the record projection, is retained. Compact serialization removes formatting overhead without deleting field content.

Durable Test Case generation previously retried the entire provider operation if persistence or attachment retention later raised a generic capacity/circuit error. Those post-generation errors now stop automatic generation replay and report how many draft cases were already saved. Existing draft idempotency keys remain intact.

## Verification and limits

Behavioral tests capture actual application request bodies and provider policies. They exercise one-correction limits, shared parser/schema failure codes, rejected full-context reuse, sanitized fallback evidence, exact citation identities, source-only evidence preservation, late source evidence beyond the historical repair cut, full eight-entry single-Story context, and provider dispatch counts after storage/attachment failures. Existing multimodal, cancellation, type/priority, Gherkin, provenance and private-data projection tests remain applicable.

Request byte reduction is distinct from token savings, latency or model quality. The shared telemetry records provider usage and request structure; this audit does not invent token or accuracy improvements from character counts. Optional retrieval remains governed by the selected feature or node configuration, and no global response/evidence cache is introduced.

The separately configured authoring-intent classifier remains intentional. Similarly, an automation actor's new observation, semantic review, verification repair and next section are different phases rather than automatically redundant calls. Provider network failure after dispatch remains an unknown outcome rather than authority to replay an accepted request.
