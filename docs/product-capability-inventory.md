# Current product capability inventory

Reviewed 10 September 2026 against the working application, representative services and their regression tests. **Inherited** means behavior already existed before this product-improvement turn and was inspected here. **Changed** identifies implementation added or corrected in this turn. A test reference describes the behavior covered; this inventory does not imply that every browser flow, provider account or data-volume scenario was exercised again. Validation results belong in the accompanying implementation report.

The product already has a substantial quality-management foundation. The appropriate redesign connects planning, authoring, execution and investigation around consistent scope, evidence and recovery. It must preserve recorded results and distinguish generated proposals from actual execution.

## Agent roles and action boundaries

The ten specialists are **Quality Orchestrator, Story Architect, Test Design Agent, Automation Engineer, Smart Run Planner, Failure Analyst, Bug Reporter, Bug Triage Agent, Quality Evaluator and Object Repository Curator**. Their common deliverable is a review brief grounded in permitted evidence. Only the four source agents have the separate, explicit selected-publication flow described above. A workflow connecting specialists does not acquire additional publication authority.

## Design priorities supported by the implementation

1. **Make the next useful action obvious.** Group destinations by planning, designing, automating, executing, investigating and managing. Empty states should initiate a supported workflow; failed requests should offer recovery rather than impersonating empty data.
2. **Preserve evidence and user intent.** Keep authored content, generated proposals, saved execution snapshots and current configuration distinguishable. Freeze execution inputs; preserve prior attempts; publish only selected changes.
3. **Explain availability before work starts.** Project selection, role grants, feature state and runtime readiness are separate conditions. OWASP's guidance on least privilege, per-request checks and explicit denial informed the implemented shared boundary. [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
4. **Represent operational truth.** Distinguish previews, running work, incomplete evidence, interruptions and completed reviews. Typed flag evaluation and explicit defaults informed the local policy corrections; the product does not claim to have installed an OpenFeature provider. [OpenFeature Flag Evaluation](https://openfeature.dev/specification/sections/flag-evaluation/)
5. **Measure before broad claims.** Source inspection and regression tests establish specific behaviors. Production-scale throughput, cross-provider reliability, translation completeness and longitudinal AI answer quality require separate measurements. A coherent shared foundation is implemented; an exhaustive redesign of every inherited form is not claimed.
