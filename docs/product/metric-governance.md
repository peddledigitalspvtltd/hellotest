# Metric governance

Administration → **Metric governance** lists 72 measurement definitions in grouped families. Seven formulas expose numeric parameters. Ten historical or operational references are read-only; they do not advertise editable runtime settings. The workspace Settings editor and its legacy metric write path are retired.

The editor separates the deterministic definition and numeric formula values from organization review criteria and version history. Native formula structure, project authorization, evidence selection and denominators stay application-enforced. Administrators can change only registered weights, thresholds, limits and bounded review text. Values must satisfy the catalog's range/step constraints; portfolio weights must total exactly 100%. Existing legacy configuration remains effective until publication.

`services/platform/shared/metricCatalog.json` is the common source for metric descriptions, criteria defaults and numeric parameter definitions. The frontend registry and portfolio calculator read the same catalog. Published metric values overlay the existing workspace-preference read contract, so portfolio calculations and metric review surfaces receive the published values without changing their project access boundaries. The shared formula normalizer keeps displayed effective legacy values consistent with calculation inputs. Application model reviews resolve their relevant organization criteria on the server at the model boundary; browsers no longer concatenate the same criteria into assurance requests. Agent and native-task execution uses the saved node/agent rubric and does not read administrator-authored metric review text. Native scores, evidence denominators and authorization checks remain application contracts. The frontend prompt/criteria hook refreshes on focus and polls every 60 seconds.

Save draft does not change live calculations. Publish requires an expected revision and uses a PostgreSQL transaction-scoped advisory lock to prevent lost updates. Conflicts return HTTP 409; Reload latest makes reconciliation explicit. Publications and restores retain an administrator audit entry and configuration fingerprint. Thirty separate version snapshots are retained. Restore publishes a historical configuration as a new version. The admin editor protects unsaved changes during navigation and page unload.

Every `/admin-portal/metric-governance` endpoint requires a current authenticated workspace administrator. The old `/settings/workspace-preferences` endpoint returns `METRIC_GOVERNANCE_MOVED` for metric writes, including whitespace-normalized keys. Other workspace preferences keep their existing behavior.

Story backlog and release readiness checklists are included as fixed deterministic metrics. Their organization review criteria appear beside the checklist methodology and use the same published preference contract. Review text cannot change the five-check denominator, content-hash validation, evidence checks, or release approval authority.

The inventory maps all 30 supported native dashboard metrics to exactly one active canonical definition. Equivalent scoped record counts share a definition rather than creating competing controls. Similar labels with different status sets or denominators retain distinct definitions. Historical Jira age/resolution and removed analytics formulas remain inspectable with their saved configuration, but reject publication. Model transport counts, latency, reported total/cached input tokens, unknown usage and trace-write failures are measured observations, not tunable formulas or AI correctness scores.

The catalog also documents criterion-level acceptance coverage, release gates, quality graph completeness, comparable-attempt variability, change-impact signals, Defect triage field coverage, Story grooming checklist coverage, and draft contract checks. Knowledge metrics separately describe retrieval rank, evidence sufficiency, structural document quality, claim support and deterministic fixture evaluation. Empty extraction now yields poor quality and requires review. None of these measurements establishes semantic accuracy, calibrated certainty or approval.

Relevant review criteria are bounded to a 12,000-character packet, with explicit excerpt notices and complete applied-metric trace identities. Lexical/metadata assurance suggestions preserve the requested objective: focused functional Stories do not acquire mandatory NFR or benchmark requirements, and positive/manual standalone cases do not acquire mandatory negative cases, Story links or execution-history requirements. Authored-design formulas now measure scope/acceptance fields, action/result completeness and declared local input references. Optional metadata, unrelated coverage categories, automation, approval and run history do not raise or lower these scores. Observed execution remains separate, with an explicit unavailable disclosure when no run evidence is supplied. These structural scores do not establish semantic quality.
